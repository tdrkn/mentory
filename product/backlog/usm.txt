# User Story Map: Mentory MVP

Дата ревизии: 2026-05-20

Источник:
- Последний DOCX-отчет `1-Отчет_обновленный.docx`.
- Прототип в Figma (выгрузка PDF "Figma basics.pdf", 72 экрана) — приоритетная UX-спецификация.
- Текущий код проекта используется как проверка статуса реализации.

Принятый подход:
- US/UC ниже фиксируют target/course baseline из отчета и прототипа.
- Комментарии "as-is" показывают, как это сейчас представлено в коде.
- Где прототип отходит от отчёта, фиксируем "Figma:" с пометкой "приоритет — прототип".
- Подробная матрица расхождений лежит в `product/gaps/requirements-gap.md`.
- План приведения к прототипу: `product/gaps/figma-alignment-plan.md`.

## Сводка ключевых правок из Figma-прототипа (2026-05-20)

- **Регистрация**: поля `Имя` и `Фамилия` раздельные, не одно `ФИО`.
- **Вход**: только email + пароль, без username.
- **Админка**: отдельный экран `/admin/login` с login + паролем (>=16 символов) + 6-значным кодом (2FA).
- **Профиль ментора (публичный)**: в правой колонке табы `Сессия` / `Подписка`, выбор карточки, единственная кнопка `Забронировать` снизу. Показывается «Ближайший свободный слот» и хинт «Слот удерживается на 10 минут для оплаты».
- **State machine заявки**: `mentee submit → mentor approves → mentee pays → session held → completed`. Сейчас код делает `pay → mentor approves`. Прототип меняет порядок.
- **Заявка**: одно поле `Мотивационное письмо` (без отдельного `goal`), плюс mentor может приложить `Комментарий для менти` при approve/reject.
- **Mentor «Управление заявками»**: 5 табов — `В ожидании / Одобренные / Оплаченные / Отклонённые / Все`. Сейчас есть только `requested/paid/booked` без отдельного «Одобрено и ждёт оплаты».
- **Mentee «Управление заявками»**: табы `Одиночные сессии` / `Подписки`, под ними `В ожидании / Одобренные / Отклонённые / Все`. В `Одобренных` показано «Ожидает оплаты» и CTA `Оплатить заявку`.
- **Видеосвязь**: ментор вставляет внешнюю ссылку через поле `Прикрепить ссылку на сессию` в карточке слота `Мои сессии`. Подтверждает report wording «внешняя ссылка в чате»; текущий `video_rooms`+Daily placeholder избыточен.
- **Финансы (mentor)**: 4 KPI-карточки (`Общий заработок` / `Доступно к выводу` / `Проведённые сессии` / `Рейтинг`) + табличная история выплат (Менти / Сессия / Дата выплаты / Статус / Сумма) + список способов вывода с masked номером карты и кнопкой `Удалить`.
- **Валюта**: везде `RUB`, не USD.
- **Профиль mentee**: блоки `О себе / Цели / Хобби / Навыки / Карьера (Образование, Должность, Место работы, Сфера деятельности)`. Поле `Цели` сейчас сохраняется как `[]` — это баг.
- **Mentor «Мои сессии»**: tabs `Предстоящие / Прошедшие / На согласовании / Все` + блок `Свободные временные слоты`.
- **Оценка**: отдельный экран `Оцените ментора` со звёздами и textarea, открывается по кнопке `Оценить ментора` из прошедшей сессии.
- **Регалии (админка)**: отдельный лист `Новые заявки на верификацию данных` с id, кнопками `↓` (скачать), ✓/✗ (approve/reject), `Чат`.
- **Поддержка (админка)**: лист `Новые заявки в поддержку` с id, типом, ФИО, ролью (Ментор/Менти), кнопками `БД`/`Чат`.

## 1. Актор: Пользователь

### US1. Регистрация и вход

Как пользователь, хочу создать аккаунт и войти в систему, чтобы пользоваться возможностями платформы.

Критерии приемки из отчета:
- Пользователь вводит email, пароль и повтор пароля.
- Пользователь вводит имя и фамилию.
- Пользователь выбирает роль: ментор или менти.
- Регистрация доступна только после согласия с пользовательским соглашением.
- При некорректных данных система показывает ошибку.
- Пользователь может перейти к авторизации и восстановить пароль.

As-is:
- Реализовано строже отчета: есть `username`, email verification gate, explicit `termsAccepted`, password reset, lockout после 5 ошибок на 15 минут.

### US2. Структурированный профиль

Как пользователь, хочу заполнить структурированный профиль, чтобы информация обо мне была актуальной и консультация была полезной.

Критерии приемки из отчета:
- У mentor и mentee разные наборы полей.
- Mentor указывает регалии, образование, навыки, сферу деятельности, услуги и планы подписок.
- Mentee указывает образование, навыки, цели и прочий контекст.
- Обязательные поля валидируются, профиль можно сохранить и редактировать.
- Заполненная информация может уходить на админскую валидацию.

As-is:
- Профили mentor/mentee реализованы.
- Полная админская pre-publish валидация профиля не является обязательным gate; regalia проверяются отдельно.

### US3. Чат между участниками

Как пользователь, хочу общаться с ментором/менти в чате для уточнения запроса и деталей встречи.

Критерии приемки из отчета:
- Текстовые сообщения отображаются обеим сторонам.
- Видно время отправки/статус.
- История переписки сохраняется.
- Чаты доступны в каталоге чатов.

As-is:
- Реализованы REST messages + Socket.IO events, typing/read, история и вложения.

### US4. Видеосессии

Как пользователь, хочу посещать сессии в формате видеозвонков, чтобы занятия проходили эффективно.

Критерии приемки из отчета:
- Участники могут обменяться ссылкой на видеозвонок в чате.
- Ссылка сохраняется в истории и доступна обеим сторонам.

As-is:
- Реализован `video_rooms` placeholder через `GET /sessions/:id/video` с provider `daily`.
- Это отличается от report-only модели "внешняя ссылка в чате".

## 2. Актор: Менти

### US5. Поиск ментора

Как менти, хочу искать менторов по критериям, чтобы быстро найти релевантного эксперта.

Критерии приемки из отчета:
- Поисковая строка и фильтры.
- Фильтры: навыки, минимальная/максимальная цена, рейтинг, сфера деятельности, должность.
- В карточке видны имя, цена от минимальной, рейтинг, должность, количество сессий.
- При отсутствии результатов система предлагает изменить фильтры.

As-is:
- Каталог и фильтры реализованы; точный набор полей отличается от отчета.

### US6. Просмотр профиля ментора

Как менти, хочу изучить профиль ментора, чтобы понять, подходит ли он под мой запрос.

Критерии приемки из отчета:
- Видна основная информация, фото, рейтинг.
- Видны регалии, образование, навыки, должность, сфера деятельности.
- Можно выбрать формат: единичная сессия или подписка.
- Из профиля можно перейти к записи или чату.

As-is:
- Профиль, услуги, rating/reviews и слоты реализованы.
- Подписки существуют отдельным workspace flow.

### US7. Запись к ментору

Как менти, хочу записаться к ментору на единичную сессию или купить подписку, чтобы получить консультацию.

Критерии приемки из отчета:
- Для единичной сессии выбирается слот, видны стоимость и формат.
- Менти может указать имя, фамилию, мотивационное письмо.
- Создается заявка со статусом "на согласовании/запланировано".
- Менти получает подтверждение или отклонение.
- Для подписки указываются цель и мотивационное письмо.

As-is:
- Разовая запись реализована как `POST /booking/hold`, где создается `Session` со статусом `requested`.
- Отдельной таблицы `applications` нет.
- Цель и мотивационное письмо сохраняются в `requestGoal` / `requestMotivation`.
- После оплаты session становится `paid` и ждет решения ментора; после подтверждения ментора становится `booked`.
- Подписка создается как `pending` request с goal/motivation; workspace открывается после approval.

### US8. Оплата сессий и подписок

Как менти, хочу оплачивать сессии и подписки, чтобы получать услуги ментора.

Критерии приемки из отчета:
- Перед оплатой показаны сумма, длительность, комиссия/налоги и правила возврата.
- Доступны способы оплаты: QR, карта, CBR.
- Ошибка оплаты показывается пользователю.
- После успешной оплаты отправляется чек/подтверждение.
- Повторная оплата одной сессии невозможна.

As-is:
- Разовый mock-acquiring flow реализован.
- Payment provider моковый.
- Подписки не имеют полноценной оплаты в текущем API.

### US9. Отзыв о менторе

Как менти, хочу рецензировать ментора, чтобы высказать свое мнение.

Критерии приемки из отчета:
- Отзыв доступен только после проведенной сессии.
- Оценка 1..5 и текст до 10000 символов.
- Отзыв отображается в профиле ментора.
- Есть ограничение против накрутки: отзыв после завершения и с учетом окна 24 часа.

As-is:
- Реализовано: `completed` session, +24h, rating 1..5, unique review per session.

## 3. Актор: Ментор

### US10. Тарифы и форматы работы

Как ментор, хочу устанавливать тарифы для разных форматов работы, чтобы предлагать удобные варианты.

Критерии приемки из отчета:
- Ментор задает стоимость разовой сессии и подписки.
- Некорректная стоимость не сохраняется.
- Тарифы отображаются в профиле.

As-is:
- Реализованы `mentor_services` и `mentorship_plans`.

### US11. Подтверждение или отклонение запросов

Как ментор, хочу подтверждать или отклонять запросы, чтобы работать с подходящими менти.

Критерии приемки из отчета:
- Есть страница "Управление заявками".
- Можно фильтровать одиночные сессии и подписки.
- Видны профиль менти, чат, формат, выбранный слот, цена и мотивационное письмо.
- Ментор может принять/отклонить и оставить комментарий.
- Если ментор не отвечает 3 дня, заявка автоматически отменяется.

As-is:
- Есть `requested/paid` session requests, dashboard и автоотмена stale requests.
- Подписочные заявки реализованы через `pending/rejected` statuses.
- Mentor approval API: `PATCH /sessions/:id/confirm|reject` и `PATCH /subscriptions/:id/status`.
- Комментарий к решению остается backlog для UX/audit детализации.

### US12. Календарь и рабочие окна

Как ментор, хочу гибко управлять календарем сессий, чтобы оптимизировать свое время.

Критерии приемки из отчета:
- Ментор добавляет/удаляет свободные слоты.
- Видит предстоящие и прошедшие сессии.
- При конфликте система предупреждает и предлагает перенос/отмену.

As-is:
- Реализованы availability rules, exceptions, slot generation и schedule UI.
- Сложные сценарии переноса требуют отдельной доработки.

### US13. Автоматическое начисление оплаты

Как ментор, хочу получать оплату автоматически после сессии.

Критерии приемки из отчета:
- После статуса "проведена" запускается начисление.
- Если нет активных обращений в поддержку, начисление происходит через 5 рабочих дней.
- Начисляется сумма за вычетом комиссии платформы.
- Повторное начисление по одной сессии невозможно.
- При сбое создается ошибка и отправляется уведомление.

As-is:
- При `completeSession` создается delayed pending payout с `availableAt` через 5 рабочих дней.
- Активные complaints по session блокируют создание/процессинг payout.
- Повторное начисление защищено уникальным `Payout.sessionId`.
- Реальный payout provider/job scheduler пока не реализован.

### US17. Настройка способа вывода

Как ментор, хочу выбрать способ получения средств.

Критерии приемки из отчета:
- Доступны банковская карта, CBR, электронный кошелек, расчетный счет.
- Пользователь вводит платежные данные и подтверждает кодом.
- Ошибки платежных данных обрабатываются.

As-is:
- Есть mock payout methods и request payout.
- Реальной проверки платежных данных и code verification нет.

## 4. Актор: Администратор / Платформа

### US14. Обработка жалоб

Как администратор, хочу обрабатывать жалобы пользователей, чтобы улучшать клиентский опыт.

Критерии приемки из отчета:
- Пользователь создает жалобу на пользователя, контент или сессию.
- Жалоба попадает в раздел поддержки с контекстом.
- Администратор берет в работу, отвечает, выносит решение.
- Действия администратора логируются.

As-is:
- Реализованы complaints, complaint messages, attachments, status updates, assignment, audit.

### US15. Модерация контента

Как администратор, хочу модерировать контент пользователей, чтобы поддерживать качество платформы.

Критерии приемки из отчета:
- Администратор видит профили, описания, отзывы, сообщения.
- Может скрыть/отредактировать/удалить контент.
- Пользователь получает уведомление с причиной.
- Действия фиксируются в журнале.

As-is:
- Есть `moderation_actions` и audit.
- Полный content moderation UI не реализован.

### US16. Верификация регалий менторов

Как администратор, хочу верифицировать документы менторов, чтобы гарантировать достоверность информации.

Критерии приемки из отчета:
- Ментор отправляет PDF до 128MB.
- В админке есть очередь документов.
- Администратор может подтвердить/отклонить, скачать документ, открыть чат.
- При отклонении ментор получает комментарий/уведомление.
- При серьезном нарушении возможна блокировка.

As-is:
- Upload/review/download/comment реализованы.
- Deep-link в чат по конкретной regalia-заявке требует доработки.

## 6. Приоритет ближайших продуктовых решений

1. Утвердить payment behavior для подписок.
2. Утвердить production payout provider/job scheduler.
3. Утвердить ВКС: external link in chat или platform-generated `video_rooms`.
4. Утвердить production storage: local uploads или MinIO/S3.
5. Утвердить NFR evidence scope: load tests, backups/RTO/RPO, retention, DWH.
